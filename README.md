# Дзен счётчик 🪷

**Медитативный счётчик повторений** — веб-приложение (PWA) + Android APK.

Клон [zenrhythm-acpcbeeg.manus.space](https://zenrhythm-acpcbeeg.manus.space/) с переработанным
интерфейсом, исправленной точностью интервалов и расширенной палитрой тем.

![Иконка приложения](docs/icon-preview.png)

## Что нового по сравнению с оригиналом

| | Оригинал | Дзен счётчик |
|---|---|---|
| Точность тиков | `setInterval` — дрейф накапливается | абсолютное планирование по `performance.now()`, дрейф не копится |
| Интервал | шаг 100 мс, отображение «×100мс» | шаг 10 мс, отображение в мс/секундах + быстрые пресеты |
| Темы | 6 | **14**: Природа, Тишина, Мистика, Йога, Эзотерика, Свечи, Тепло, Море, Космос, Океан, Лес, Уголёк, Сакура, Моно |
| Обратный отсчёт | просто число | **красочная анимация**: радужные цифры, расходящееся кольцо, вибро-отклик |
| Заставка | нет | **анимированная**: рисуется энсо, распускается лотос, всплывают частицы |
| Значок | сгенерированный PNG | авторский SVG: энсо + лотос, адаптивная иконка Android |
| Компоновка | плотная | крупная кнопка старта, карточка интервала, транспорт-ряд, чипы пресетов |
| Автоцикл | нет | есть: после цели счётчик сам начинает заново |
| Экран телефона | может гаснуть | экран удерживается включённым, пока идёт счёт |

## Возможности

- 🎯 **Точный ритм** — тики планируются по абсолютной шкале времени: `nextAt += interval`
  с подстройкой по `performance.now()`. Ошибка одного тика не накапливается в серии.
- 🎨 **14 тем** с собственным градиентом, свечением и частицами фона.
- 🔔 **6 звуков** (щелчок, колокольчик, гонг, поющая чаша, капля, ом) + загрузка своего,
  вибрация или «звуки+вибрация».
- 📿 **Пресеты**: цель, интервал, направление, отсчёт, звук, автоцикл — всё в одном профиле.
- 🔢 **Счёт вверх/вниз**, сброс, процент прогресса, бусины малы по кругу циферблата.
- 💾 Состояние сохраняется локально и переживает перезагрузку.

## Запуск веб-версии

```bash
cd web
python3 -m http.server 8080
# открыть http://localhost:8080
```

## Сборка APK

Нужны JDK 17 и Android SDK (`platforms;android-34`, `build-tools;34.0.0`).

```bash
export ANDROID_HOME=/path/to/android-sdk
./scripts/build-apk.sh              # сам выберет способ сборки
# APK появится в dist/zen-counter-v1.0.0.apk
```

Скрипт сам определяет, каким путём собирать:

| Способ | Когда | Что нужно |
|---|---|---|
| **Gradle** (`--gradle`) | Linux/macOS/Windows на x86_64 | `gradle`, AGP скачивает `aapt2` из Maven |
| **Ручной** (`--manual`) | ARM64 (Termux, Apple Silicon без эмуляции), где `aapt2` не запускается | `aapt`, `zipalign`, `apksigner` из пакетного менеджера + `d8` из build-tools |

На x86_64-машине Gradle-путь предпочтительнее (пишет APK под релизную подпись),
на ARM64 используется `scripts/build-apk-manual.sh` — та же цепочка, что у AGP,
только из ARM-версий тулзов:

```bash
./scripts/build-apk-manual.sh       # aapt package → javac → d8 → zipalign → apksigner
```

Сборка вручную через Gradle напрямую:

```bash
rsync -a --delete web/ android/app/src/main/assets/www/
cd android && ./gradlew assembleRelease
```

## Тесты

```bash
cd tests
npm install
node run-tests.mjs            # добавьте --no-original, если нет интернета
```

Тесты идут в **Firefox** (Playwright): Chromium в песочницах вроде proot/Android
обычно не стартует. Если Playwright жалуется на зависимости системы — запустите
`npx playwright install-deps firefox`; сам стенд дополнительно отключает
песочницу контент-процесса Firefox, поэтому ничего править не нужно.

Проверяются: точность интервалов (100/300/700 мс), сравнение с оригиналом и с
`setInterval`-эталоном в той же вкладке, отсчёт, достижение цели, пресеты, темы,
сохранение состояния, адаптивность; снимаются скриншоты.
Результат — `docs/test-report.md`.

Последний прогон — **18/18** (`docs/test-report.md`). Главный показатель — медианный
дрейф типичного тика, он стабилен 0.0 мс на любых интервалах:

| Движок | Интервал | Дрейф (медиана) |
|---|---|---|
| Наш (абсолютное планирование) | 100 / 300 / 700 мс | **0.0 мс** |
| `setInterval`-эталон (та же вкладка) | 100 мс | 1.0–3.3 мс |
| Оригинал сайта | 500 мс | 1.0–2.0 мс |

Накопленная ошибка за 200 тиков тоже всегда ниже, чем у `setInterval` в той же
вкладке (та же нагрузка системы, одинаковые условия) — точные цифры конкретного
прогона приведены в отчёте. Суммарное отклонение при этом зависит от загрузки
машины: таймеры ОС «запаздывают» пачками, но наш движок возвращается к плановому
расписанию, а `setInterval` уходит всё дальше.

## Как это работает (точность)

Вместо `setInterval(fn, N)`, где каждая итерация стартует от момента завершения
предыдущей (ошибки складываются), используется цепочка `setTimeout` с абсолютным
расписанием:

```js
function onTickAlarm() {
  fireTick();                     // звук, вибрация, счёт, анимация
  nextTickAt += engineInterval;   // плановая точка, а не «сейчас + N»
  if (nextTickAt < performance.now() - engineInterval) {
    nextTickAt = performance.now() + engineInterval; // после сна вкладки — ресинк
  }
  armTick();                      // setTimeout до следующей плановой точки
}
```

Плановая точка не сдвигается от фактического времени срабатывания, поэтому
систематический дрейф за серию тиков стремится к нулю, а «заснувшая» вкладка
не порождает лавину пропущенных тиков.
